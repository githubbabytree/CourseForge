# Provider probes and TTS pronunciation lexicons

Provider checks are opt-in. Only a platform administrator can trigger one; auditors can read persisted, version-bound results. Production currently has real exact-origin OpenAI-compatible text and multimodal probes. Search, design, TTS, deck and video return unhealthy `unavailable` until their governed probe adapters are added. A missing adapter never implies health, while a multimodal probe failure must be treated as an incompatibility until the same bounded image and structured-output request succeeds. Results exclude endpoints, secret references and model filesystem paths.

Pronunciation lexicons use immutable draft, published and inactive versions with a content hash. Migration 014 stores the snapshot binding; no later migration is required. A TTS run resolves only the version fixed by that snapshot, re-hashes its bounded entries, sends the exact id/version/hash/entries through sidecar protocol v2, and rejects request tampering or mismatched response provenance. The runner must prove it consumed the same hash before the worker returns audio. The speech manifest pins the applied lexicon id and hash. A request-level lexicon id is accepted only when it equals the snapshot binding; it cannot override the snapshot. Snapshots without a lexicon continue to synthesize with `pronunciationLexicon: null` and record null manifest provenance.
