# Durable workflow boundary

When `DATABASE_URL` is configured, CourseForge uses the PostgreSQL lease queue introduced by migration 008 and extended by migration 019. Explicit job kinds now cover `design-plan`, `deck-build`, and `release-package` in addition to the content/media pipelines. A descriptor stores only project/actor IDs, the immutable runtime snapshot ID, input artifact/template/direction/asset IDs, their captured SHA-256 hashes, bounded scalar options, and one canonical input hash. Prompt bodies, source text, provider credentials and resolved secrets are intentionally absent from the descriptor, event history and failure audit.

Workers atomically claim a job only when its lease is absent or expired, heartbeat while a stage runs, and update the job document plus its uniquely sequenced event in one SQL statement. A repeated checkpoint therefore cannot duplicate an event. Startup scans queued/running jobs with expired leases and reconstructs the executor through the dispatcher. Failed jobs are not automatically retried; an authorized editor can request `POST /v1/jobs/{jobId}/resume`. Cancellation uses `POST /v1/jobs/{jobId}/cancel` and is observed at the next stage boundary.

Design planning and deck building return `202` with the real job document. Before enqueue, the API verifies same-project artifacts and captures material/plan/template/direction/brand-asset bindings and hashes. The worker verifies those bindings again and fails closed on cross-project data, tombstones, hash drift, or a missing published template/snapshot. A resumed design-plan job reuses its persisted plan artifact; a resumed deck-build job reuses its complete DeckSpec/Reveal/render-manifest bundle and does not create a second document revision when the generated artifact is already active.

Publication enqueues `release-package`. The stage persists a deterministic WebPPT artifact and verified release manifest once. Downloads never invoke packaging: GET resolves only a completed manifest, revalidates its project/revision/input/resource bindings, and reads the selected blob. A missing, stale, withdrawn, tombstoned, or hash-invalid release fails closed. This keeps ZIP construction and artifact writes out of GET handlers.

This implementation is a runnable PostgreSQL-backed linear queue, not Temporal. It does not yet interrupt an external provider call mid-stage, schedule exponential retries, or provide a general DAG/activity model. Times are stored as UTC `timestamptz`/ISO-8601 values; user-visible rendering converts them to Asia/Shanghai (UTC+8).

Without PostgreSQL, the API retains the synchronous design/release path only outside `NODE_ENV=production` for local development and tests, and marks its audit/response as `development-sync`. Production rejects these heavy operations unless the durable queue is configured. `/health` and `/version` report `workflowBackend` as either `postgres-lease-queue` or `in-memory-development`, so the deployment boundary is observable.
